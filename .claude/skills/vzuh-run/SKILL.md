# Сайт vzuh.run — рабочий скилл

Статический сайт бегового клуба «ВЖУХ» (Москва, тренер Александр Трофимов)
на shared-хостинге Beget + PHP-сервисы: публикация расписания, база знаний,
генератор планов подготовки (GigaChat + детерминированная сшивка на сервере).
Хостинг = рабочая область пользователя; репозиторий = витрина кода.

## Карта структуры

```
index.html, knowledge.html, kb/*.html   — страницы (25 HTML: menu/footer дублируются)
editor.html / kb-editor.html            — редакторы расписания / базы знаний
publish.php / kb.php / reviews.php      — PHP-приёмники публикации (пароли из secrets.php)
ai-plan/plan.php                        — генератор планов (весь конвейер в одном файле)
ai-plan/index.html                      — форма анкеты → план (xlsx)
ai-plan/data/ out/ model-log.txt diag.php  — runtime: НЕ в git, НЕ заливать в вебрут
data/schedule.js, data/knowledge.js     — контент (публичный, в git есть)
data/reviews.js, data/_backups/         — персональные данные — НЕ в git
tools/                                  — python: build_knowledge.py, generate_kb_pages.py,
                                          kb_edit.py, devserver.py (превью статики)
secrets.php                             — реальный ключ GigaChat + пароли. gitignored;
                                          на хостинге лежит в корне, один раз
.claude/skills/vzuh-run                 — этот скилл (в git)
github/                                 — доки репо: README, чек-лист, профиль
README.md, README-расписание.md, README-база-знаний.md  — инструкции в корне
Logs/ _Ненужности/ *—копия.html         — локальный мусор, игнорируются, не трогать
```

Полное ограничение генератора планов: `ai-plan/генерация планов — ограничения — сводка.md`.

## Секретная схема (критично)

Единственный источник секретов — `secrets.php` в корне (gitignored): ключ
GigaChat, флаг его base64-формы, пароль модели Pro, пароли публикации
расписания и базы знаний. Код (`plan.php`, `publish.php`, `kb.php`) делает
`require secrets.php` + заглушки `if (!defined(...))` — репо-версия инертна,
хостинг-версия работает только вместе с secrets.php (заливать парой).

Правила:
- НИКАКИХ значений секретов в файлы, коммиты, логи, чат, архивы — включая
  grep-шаблоны. Для проверки перед push писать шаблон без литералов
  (например, искать base64-префикс ключа из secrets.php программно, читая
  значение из файла, а не из текста скилла/скрипта).
- `ai-plan/Gigachat_API/`, `data/reviews.js`, diag-файлы — никогда не в git
  и не на прод.
- Ключ GigaChat подлежал перевыпуску; если пользователь скажет «ключ
  сменил» — обновить значение в локальном secrets.php, напомнить про хостинг.

## Сценарии правок

### Страницы сайта (HTML/CSS/JS)
Меню (`<nav>`) и футер повторяются во всех 25 HTML-файлах, включая
`kb/s01..s21.html` — править синхронно. После правки проверять
`grep -c` правленного фрагмента по всем файлам — счётчики должны сходиться.
Sitemap.xml обновлять при добавлении/перемещении страниц.

### Расписание недели
Контент: `data/schedule.js` (подключается фронтендом). Путь редактирования:
`editor.html` (пароль = PUBLISH_PASSWORD из secrets.php) → `publish.php` →
перезапись `data/schedule.js`. Инструкция: `README-расписание.md`. Прямая
правка JS допустима — формат см. в самом файле (массив недель с датами).

### База знаний
Контент: `data/knowledge.js` → страницы `kb/s01..s21.html` генерируются
`tools/generate_kb_pages.py`. Редактирование: `kb-editor.html` (пароль =
KB_PASSWORD) → `kb.php`; офлайн — `tools/kb_edit.py`. Инструкция:
`README-база-знаний.md`. После контентных правок прогонять генератор
страниц, чтобы kb/*.html не расходились с knowledge.js.

### Генератор планов (ai-plan/plan.php)
Один файл, весь конвейер: анкета-валидатор → GigaChat (скелет) →
детерминированная сшивка. Пер-день: recWeek/race/raceEve/raceQuiet/raceRest/
model row/train-slot/forceEasy/округление. Пер-неделя: D FIX (фолбек
Ф→Горка→И→П→ЦМТ), D DUP, QUAL DUP, D MOVE, MAXD FIX, VOL FIX, D MIN,
KM SYNC, CMT MIN, WEEK FIX, INT FIX, THR FIX. Прогрессивные правки —
только с бэкапом рабочей версии. После правки PHP:
1. Баланс скобок python-чекером (`{ } ( ) [ ]` — глубина в конце все 0):
   локального PHP нет, `php -l` недоступен.
2. Логику проверять симуляционным python-скриптом (парсинг xlsx-выгрузки
   через regex `<c r="...">...`, inline strings `<is><t>`) — несколько
   случаев до/после правки.
3. Финальная проверка жизни: пользователь генерит тестовый план на
   хостинге, смотреть `ai-plan/model-log.txt` — там метки слоёв
   (CMT MIN, CHUNK FAIL, 429-фолбек Pro→Lite и т.д.).

### README
- Корневые `README*.md` — инструкции: обновлять при изменении процедур
  (публикация расписания, база знаний, деплой). Пароли в них не писать.
- `github/README.md` — readme репо: обновлять при изменении архитектуры,
  структуры, фич. Язык — русский (русскоязычный проект).

### Проверка ошибок сайта
- Статика: `python tools/devserver.py`, смотреть в браузере.
- Логи хостинга: `Logs/` (формат Beget: сайт IP [дата] "запрос" код размер);
  смотреть 4xx/5xx по PHP-файлам.
- Генерация: `ai-plan/model-log.txt` (429 → фолбек, CHUNK FAIL → частичный
  ответ модели).
- PHP-синтаксис: только python-чекер скобок.

## Деплой на Beget

Хостинг зеркалит корень папки. Заливать: HTML/CSS/JS, kb/, PHP-файлы —
ТОЛЬКО с актуальным `secrets.php`. Не заливать: Gigachat_API/, ai-plan/data/
(runtime на хостинге свой), out/, model-log.txt, diag.php/delete-diag.php,
Logs/, xlsx, локальные .md-инструкции. После деплоя проверить в браузере
главную + публикацию + генерацию плана; временно залитые diag-файлы удалить.
