## Рабочий цикл — три команды

```bash
cd C:\AL\AI\newsite     # терминал в папке сайта
git add .               # добавить все изменения (или конкретный файл: git add index.html)
git commit -m "что изменил"   # снимок с подписью
git push                # уйти в GitHub
```

Лайфхак: **коммитить ДО правок, а не после**. Перед серьёзной правкой
`plan.php` или страниц:

```bash
git add . && git commit -m "снимок перед правкой X" && git push
```

Тогда всегда есть точка отката «как работало».

## Синхронизация с хостингом (Beget)

Git и хостинг — две отдельные копии, сами не синхронизируются. Порядок:

1. Правка файла локально (или редакторами — они меняют `data/*.js`).
2. `git add . && git commit -m "..." && git push` — снимок в GitHub.
3. Заливка изменённых файлов на Beget (файловый менеджер панели или FTP).
4. Проверка браузером — **Ctrl+F5**.

Так GitHub = «до правки», хостинг = «после правки»; поломка на хостинге
откатывается к предыдущему коммиту.

**PHP-файлы** (`plan.php`, `publish.php`, `kb.php`) на хостинг заливать
только вместе с `secrets.php` (он залит один раз; повторно — только после
смены ключа/паролей).

## Откат к рабочей версии

```bash
git diff                         # что изменилось с прошлого коммита
git restore index.html           # откатить файл к последнему коммиту
git restore .                    # откатить всё незакоммиченное
git log --oneline -10            # последние снимки
git checkout <hash> -- файл      # вернуть одну версию файла из старого коммита
git revert <hash>                # отменить коммит новым коммитом
```

## Редактирование прямо на GitHub

Кнопка **карандаш** у файла на github.com → правка → «Commit changes».
Удобно для мелких правок README/текстов с любого компьютера.
После этого в терминале: `git pull`, чтобы локальная копия догнала.

## Ветки (опционально, для экспериментов)

```bash
git switch -c experiment     # новая ветка — main остаётся стабилен
... работа, commit, push ...
git switch main              # вернуться на стабильную версию
git merge experiment         # влить удачный эксперимент
```

## Шпаргалка типовых ситуаций

| Ситуация | Действие |
|---|---|
| Правка сделана, сайт на хостинге проверен | `git add . && git commit -m "..." && git push` |
| Правка сломала сайт | `git restore файл` (или заливка файла из прошлого коммита на хостинг) |
| Поправил файл через GitHub в браузере | `git pull` локально |
| Сравнить текущий plan.php с недавним | `git diff HEAD~1 ai-plan/plan.php` |
| Случайно закоммитил лишний файл | `git rm --cached файл` + дополнить `.gitignore` |
| Сайт сломался, что менялось — неясно | `git log --oneline`, восстановить файлы из последнего рабочего коммита |

Смежные инструкции: `README.md` (работа с сайтом), `README-расписание.md`
(расписание), `README-база-знаний.md` (база знаний).
