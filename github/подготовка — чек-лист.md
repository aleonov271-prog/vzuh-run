# GitHub: публикация сайта «ВЖУХ» — чек-лист подготовки

Рекомендация: **публичный репозиторий** — код статического сайта и
генератора планов с LLM-сшивкой хороший портфолио-материал. Но перед
первым push из проекта нужно убрать три вида секретов и локальный мусор.

---

## Шаг 1. Вынести секреты из кода (до первого коммита)

Сейчас пароли/ключ зашиты константами прямо в файлы:

| Файл | Что внутри |
|---|---|
| `ai-plan/plan.php` (~26, ~32) | ключ GigaChat API (+ его base64-форма) |
| `ai-plan/plan.php` (~41) | пароль модели Pro |
| `publish.php` (~31) | пароль публикации расписания |
| `kb.php` (~23) | пароль публикации базы |

Схема выноса — один файл `secrets.php` в корне сайта (не коммитится):

```php
<?php
// secrets.php — локальные секреты; в git не попадает (.gitignore)
define('GIGA_KEY',    '<ключ GigaChat>');
define('PRO_PASS',    '<пароль Pro>');
define('PUBLISH_PASSWORD', '<пароль публикации>');
define('KB_PASSWORD', '<пароль публикации>');
```

В коде вместо захардкоженных констант:

```php
// plan.php (вместо двух const с ключом и PRO_PASS):
if (is_file(__DIR__ . '/../secrets.php')) { require __DIR__ . '/../secrets.php'; }
if (!defined('GIGA_KEY')) { define('GIGA_KEY', ''); }
if (!defined('PRO_PASS')) { define('PRO_PASS', ''); }

// publish.php / kb.php (вместо define-пароля):
if (is_file(__DIR__ . '/secrets.php')) { require __DIR__ . '/secrets.php'; }
if (!defined('PUBLISH_PASSWORD')) { define('PUBLISH_PASSWORD', ''); }
```

На хостинге файл `secrets.php` закрывается так же, как остальные PHP
(он исполняется, по HTTP содержимое не отдаётся), и заливается один раз.

> Ключ GigaChat всё равно стоит перевыпустить (уже планировалось) — старый
> засвечивался в локальных файлах и, возможно, в истории.

## Шаг 2. Убрать из репозитория

Полный список в готовом `github/.gitignore` — его скопировать в корень
сайта перед `git init`. Не попадут: ключи, runtime-данные (`ai-plan/data/`,
`out/`, логи, выгрузки xlsx), диагностика, отзывы посетителей
(`data/reviews.js` — персональные данные не публикуем), локальные
инструкции (в «яндекс-вебмастер — инструкция.md» есть пароли),
бэкапы (`_Ненужности/`, «копия.html», Logs/).

Расписание `data/schedule.js` и база `data/knowledge.js` в репозиторий
входят — это публичный контент сайта и демо-данные для редакторов.

## Шаг 3. Первый коммит и push

Разово (терминал в корне сайта):

```
copy github\.gitignore .gitignore       # ← в корень
git init
git add .
git status                              # проверить: secrets-файлов в списке нет
git commit -m "Сайт бегового клуба ВЖУХ: статика + редакторы + генератор планов"
# на github.com: создать пустой репозиторий (без README — он уже есть)
git remote add origin https://github.com/<логин>/<имя-репо>.git
git branch -M main
git push -u origin main
```

После push посмотреть на github.com глазами файлы `plan.php`,
`publish.php`, `kb.php` — в них должны быть только пустые заглушки. Если
GitHub подсветит «Potential secrets» — вычистить до включения публичного
доступа.

**Хостинг при этом не трогается**: там остаётся текущая версия файлов
с настоящими паролями. Синхронизацию «репо = хостинг» решать после
(например, вручную при релизах).

## Шаг 4. Настройки репозитория

- **Имя**: `vzuh-run` (или `vzuh.run`).
- **Description**: «Сайт бегового клуба ВЖУХ (vzuh.run): статика + редакторы
  расписания и базы знаний + генератор планов тренировок на GigaChat с
  детерминированной сшивкой».
- **Topics**: `running`, `running-club`, `php`, `static-site`, `llm`,
  `gigachat`, `training-plan`, `xlsx`.
- **GitHub Pages не включать** — сайт уже на Beget, дубль только путает
  поисковики.
- **License**: рекомендую MIT (простой, для витрины достаточно). Файл
  `LICENSE` создать на github.com кнопкой «Add file → Create new file →
  LICENSE» или взять тут. Если хотите другой — скажите.
- **Branch protection** не нужен (работаете один), достаточно не коммитить
  напрямую secrets.

## Шаг 5. Что ещё выложить полезного (опционально)

- Скриншоты главной и плана-xlsx в `docs/` (картинки не секреты, но
  изображения посетителей в кадр не брать).
- В `ai-plan/генерация планов — ограничения — сводка.md` уже есть
  «изюминка» репозитория — в README на неё есть ссылка.
- Инструкции редакторов («расписание — инструкция.md» и др.) в репо не
  выкладывать (пароли внутри), README-файлы в корне уже покрывают нужное.

## Мини-сводка «что станет публичным»

| Публично | Не публично |
|---|---|
| все HTML/CSS/JS, kb/, tools/ | ключи и пароли (secrets.php, .gitignore) |
| plan.php с заглушками | ai-plan/data/, out/, логи, xlsx-выгрузки |
| schedule.js, knowledge.js | data/reviews.js, data/_backups/ |
| README, лицензия | локальные *.md-инструкции с паролями, Logs/, _Ненужности/ |
