# README — Редактирование базы знаний

База знаний — страница **`knowledge.html`**: заметки тренера в виде дерева
(4 группы → 21 тема → статьи) с поиском по слову. Данные живут в **одном
файле** — `data/knowledge.js`. Это единственный источник; дайджест
«Техника бега — подборка сообщений.html» больше **не используется**.

Полная подробная версия: `база-знаний — инструкция.md`. Здесь — рабочий
минимум.

## Основной способ: веб-редактор `kb-editor.html`

Открыть `kb-editor.html` (локально или на сайте: `https://vzuh.run/kb-editor.html`).

| Блок | Что делает |
|---|---|
| Слева — дерево | Группы и темы. Поле — переименование, ▲▼ — порядок, ✕ — удалить (с подтверждением). Клик по теме открывает её карточки справа |
| Справа — карточки темы | Заголовок, дата, текст. Свёрнутая карточка — клик по заголовку раскрывает. «+ Добавить карточку» — новая статья |
| Поле внизу | Вставить статьи текстом: блоки через строку `---`, первая строка блока — заголовок, вторая — дата (`2026-10-01`). Кнопка «Разобрать и добавить» |
| «📥 Загрузить файл со статьями» | То же из TXT-файла |
| «Скачать knowledge.js» | Запасной способ: файл в «Загрузки» → перенести в `data/` с заменой (имя не менять) |

### Оформление текста статьи

- перенос строки → перенос на сайте; пустая строка → абзац;
- `**текст**` → **жирный**; при необходимости — напрямую HTML
  (`<strong>…</strong>`, `<br><br>`);
- знаки `<`, `>`, `&` в обычном тексте экранируются автоматически.

## Публикация на сайт (когда база на хостинге)

1. Правки в `kb-editor.html`.
2. Внизу — блок **«Публикация на сайт»**: адрес сайта и пароль (тот же,
   что у расписания; хранятся в браузере).
3. **«🚀 Опубликовать базу на сайт»** (база ~2 МБ — отправка до минуты).
4. Открыть `knowledge.html`, **Ctrl+F5**.
5. Обновить статические страницы: локально `python tools/generate_kb_pages.py`
   и залить папку `kb/` на хостинг (без этого поисковик видит старые статьи).

> Перед каждой записью предыдущая версия сохраняется на сервере в
> `data/_backups/knowledge-prev.js` (и `-prev-2.js`). Незапубликованные
> правки автоматом держит черновик в браузере («Вернуть черновик» в шапке).

## Запасной способ: консольный `kb_edit.py` (нужен Python на своём ПК)

```
python tools\kb_edit.py list                  — все темы с числом статей
python tools\kb_edit.py list --cards s16      — статьи темы s16 (номера m…)
python tools\kb_edit.py add --topic s17 --file "пульс-зоны.txt" --title "…" --tags "пульс зоны"
python tools\kb_edit.py delete m310           — удаление с подтверждением
python tools\kb_edit.py rename s20 "Марафон: подготовка"
```

- Коды тем: `s01`…`s21` (группы `g1`…`g4`); статьи адресуются номерами `m…`.
- `add`: `--date 2026-09-30` (по умолчанию сегодня), `--tags` — теги для
  поиска (не видны на странице), `--end` — внизу темы (по умолчанию статья
  добавляется сверху).
- После `add` инструмент печатает постоянный якорь (`knowledge.html#m425`)
  — на него можно ссылаться в чатах.
- Удалённый номер не переиспользуется — старые ссылки не едут.
- Перед **каждой** правкой бэкап в `data/_backups/knowledge-ГГГГММДД-ЧЧММСС.js`
  (восстановление: копия с заменой, имя должно остаться `knowledge.js`).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| «База знаний не загрузилась…» на странице | Восстановить последний бэкап из `data/_backups/` |
| «Файл данных повреждён (не JSON)» | То же; дальше править через редактор, не руками |
| Статья не видна | **Ctrl+F5** |
| Ссылка `#m…` ничего не открывает | Статья удалена — сверить `list --cards sNN` |
| «Не удалось опубликовать (wrong_password)» | Пароль тот же, что у расписания |
| «Ошибка связи с сайтом» | На хостинге нет `kb.php` — загрузить в корень |
