# README — Работа с сайтом (клуб «ВЖУХ», vzuh.run)

![скриншот главной страницы сайта] (https://github.com/aleonov271-prog/vzuh-run/blob/main/Images/скриншот%20сайта.jpg)
Сайт — обычная статика на shared-хостинге Beget + три интерактивных
сервиса на PHP: генерация планов тренировок (`/ai-plan/`), форма отзыва
(`reviews.php`), публикация данных из редакторов (`publish.php`, `kb.php`).

Соседние подробные инструкции (не трогать без нужды — ниже их суть):
- `яндекс-вебмастер — инструкция.md` — индексация в Яндексе;
- `README-расписание.md` — недельное расписание;
- `README-база-знаний.md` — база знаний.

## 2. Как внести изменение на сайт

1. Править файл в этой папке (или через редакторы — см. README-расписание /
   README-база-знаний).
2. Залить изменённые файлы на хостинг (панель Beget → файловый менеджер,
   или FTP). Пути локальной папки = пути на хостинге.
3. Проверить браузером — **Ctrl+F5** (жёсткое обновление, без кеша).

Быстрые правки текстов страниц — прямо в HTML (`index.html` и т.п.),
структура повторяется: меню сверху, секции, подвал.

## 3. Данные, которые меняются чаще файлов

- **Расписание недели** — редактор `editor.html`, публикация кнопкой через
  `publish.php`. Подробности в `README-расписание.md`.
- **База знаний** — редактор `kb-editor.html`, публикация через `kb.php`.
  Подробности в `README-база-знаний.md`. Статические страницы `kb/`
  генерируются скриптом `python tools/generate_kb_pages.py` — руками их
  не править (после правок базы запустить генератор и залить `kb/`).
- **Отзывы** — пишутся сами через форму на сайте в `data/reviews.js`.
  Просмотр: в конце главной. Модерация — по требованию правится файл.

## 4. Сервис планов (`/ai-plan/`)

Анкета → GigaChat API (`ai-plan/plan.php`) → xlsx-план в `/ai-plan/out/`.
Три страницы: анкета, статус генерации, скачивание файла.

Ключевые настройки — константы в `plan.php`:
- `GIGA_KEY` (~строка 26) — ключ GigaChat API;
- `PRO_PASS` (~41) — пароль выбора модели Pro;
- `RATE_LIMIT` / `RATE_WINDOW` (~54–55) — лимит: **3 генерации в час с IP**.

Диски/файлы:
- `ai-plan/data/` — токен-кеш, model-log.txt — закрыта от интернета,
  лог доступен только с хостинга;
- `ai-plan/out/` — готовые xlsx, закрыта для индексации;
- `diag.php`, `delete-diag.php` — диагностика, удалять со хостинга после
  использования;
- **`ai-plan/Gigachat_API/` на хостинг не заливать** (ключи);
- локальный `ai-plan/model-log.txt` в webroot тоже не заливать.

Отладка плана: пользователь генерирует план → выгружает xlsx в
`ai-plan/` → правки plan.php (детерминированные слои сшивки) →
перезаливка plan.php.

## 5. Безопасность — красные линии

1. Ключи/пароли не публиковать: в чатах, логах, архивах, open-source.
2. Пароли на сервере: `publish.php`, `kb.php`, `plan.php` (PRO_PASS) —
   менять только через файлы на хостинге, не выносить в git/архивы.
3. После правок `diag.php` — удалить с хостинга.
4. Вебмастер/Метрика/Бизнес — владелец вручную (см. инструкцию Яндекса).

## 6. Регулярные процедуры

| Что | Как часто | Куда |
|---|---|---|
| Расписание недели | еженедельно | editor.html → publish |
| База знаний | по мере накопления | kb-editor.html → publish |
| Контент страниц | при необходимости | HTML → Beget |
| Проверка Вебмастера | раз в 1–2 недели | кабинет, см. инструкцию |
| Бэкап `data/` | перед большими правками | скачать всю папку |
